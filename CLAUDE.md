# Fantasy Edge

ESPN fantasy football (PPR, private league) helper suite: draft board (VBD, manual tap), start/sit, waiver finder w/ Sleeper trending, trade finder. Zero cost.

## Stack
Plain HTML/JS single page (`index.html`), Node proxy for ESPN cookies (`api/espn.js`, Vercel-function-shaped), local server `server.js`, hourly (7am–9pm PT) change-driven Telegram waiver alert via GitHub Actions — diffs Sleeper trending + roster injuries against state.json (actions/cache) and only calls Claude on changes; dedups sent advice.

## Live deployment
LIVE at https://fantasy-edge-lyart.vercel.app (Vercel team scope `ethan16`, project fantasy-edge; env vars LEAGUE_ID, ESPN_S2, SWID, SEASON set in production). Deploy: `vercel deploy --prod --yes`. Alerts: GitHub Actions secrets (same + ANTHROPIC_API_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID — reuse stock-agent bot; note stock-agent names its token secret TELEGRAM_TOKEN).

## Local run
`node server.js` → http://localhost:4650. Needs `.env` with LEAGUE_ID, ESPN_S2, SWID.

## Gotchas
- Vercel's build REQUIRES a server entrypoint (server.js) and only bundles files it can trace — index.html is loaded via a static `readFileSync(path.join(__dirname,...))` at module top so it gets included. Don't switch to dynamic file paths.
- `.vercelignore` excludes `.env`; secrets live in Vercel env vars, not files.
- server.js listens on `process.env.PORT || 4650` — Vercel injects PORT.
- ESPN private league needs cookies SWID (with curly braces) and espn_s2 from browser dev tools on fantasy.espn.com. They expire ~yearly; if API returns 401, re-grab them.
- ESPN player projections: `stats[]` entry with `statSourceId=1` AND `seasonId=2026`; `scoringPeriodId=0` = season total, `=N` = week N. Verified live Jul 19 2026. Without the seasonId filter you can grab LAST season's entry.
- Draft completed Aug 2026: rosters are live from ESPN on every page load (no caching), so Start/Sit and Trades reflect the real league immediately — no manual sync step. Team names are ESPN-manager-editable and change mid-season; always match a team by id, never by display name.
- Headless verification: playwright-core + system Chrome (`channel:'chrome'`), driver at scratchpad drive.js pattern.
- Sleeper trending players matched to ESPN by lowercase full name — DST/name-suffix mismatches expected, cosmetic only.
- Draft board state (drafted/mine) lives in localStorage only.
- **ESPN is not the only vote in the board's value.** `consensus()` in index.html blends, per position, ESPN's projection rank + market ADP rank + every analyst rank in `analyst-ranks.json`, equally weighted (`WEIGHTS`). The blended fractional rank maps back to points off ESPN's own projection curve (`valueAt`) — curve shape is ESPN's, ORDER is the consensus — then VBD and tiers run on that. **A source that omits a player casts no vote** (Holka stops at 150, Smyth is QB/TE only), so absence never counts as a low rank. **Guard: a 0 ESPN projection = IR/not playing, and ESPN alone ranks those** — without it a stale July analyst rank floated an Injured Reserve WR from 150th to 71st. Rows expand to show every vote; a chip flags 5+ rank disagreements. **Smyth is a tiebreaker, not an override** (`FAVOR = {Smyth:3}`, `CLOSE = 5`): his vote triples ONLY when all sources sit within 5 positional ranks: a blanket bump would let him overrule everyone exactly where they disagree most. 32 of 44 Smyth-rated players qualify; the expanded row says "close vote, Smyth weighted heavier" when it fires.
- `node scripts/draft-research.js --analyst-ranks` flattens every `draft-guide*.json` into `analyst-ranks.json` for the browser — free, local, no network. **Re-run it after dropping in a new guide** or the board won't see the new analyst. The output filename is fixed because server.js must read it on a literal path (Vercel only bundles files it can trace; a runtime glob 404s in production).
- **Tiers are computed, not asked for.** `tierize()` in index.html splits a position where the VBD gap clears `MIN_CLIFF` (8 pts) AND 2.5x the *local* median gap (rolling ±6 window). The window is load-bearing: a position-wide median is dragged near zero by the flat tail, which made all 386 players their own tier (127 cliff rows, verified live). Claude no longer returns a `tier` field — old `draft-analysis.json` entries still carry one, unread. Row badge is `RB1 · 15 left`; break rows are `↓ 14 pt RB cliff`.
- Alert state (state.json: trending ids, injury map, sent-advice hashes) persists between Actions runs via actions/cache (`key: waiver-state-${{ github.run_id }}` + restore-keys prefix). Gitignored; delete it locally to force a "first run".
- waiver-alert.js dry-runs without ANTHROPIC_API_KEY (`node --env-file=.env scripts/waiver-alert.js`): does all free fetches, logs the prompt, saves state, stops before Claude.
- Alert cron is PDT-pinned UTC (`0 13-23,0-4` = 6am–9pm PT); drifts 1h after the Nov PST switch — accepted. The 6am start is load-bearing: FAAB bids process 10am ET / 7am PDT, so 6am is the last run before the deadline.
- **ESPN league views must be sent as repeated `&view=` params, not comma-joined.** `?view=mTeam,mSettings` returns 200 but silently omits the `settings` object; `?view=mTeam&view=mSettings` includes it. `espn()` in waiver-alert.js splits on comma and rebuilds the query for this reason — don't "simplify" it back.
- League is FAAB continuous waivers: `settings.acquisitionSettings` = $1000 budget, $1 min bid, processes daily 10am ET. Per-team spend is `team.transactionCounter.acquisitionBudgetSpent`. The alert prompt lists every team's remaining budget and the system prompt requires a bid range ($ and % of remaining) on every recommended add.
- ESPN weekly actuals: `statSourceId=0`, stat ids 58=targets, 53=receptions, 23=rush att; use X-Fantasy-Filter `filterStatsForTopScoringPeriodIds` on kona_player_info. NFL schedules: `seasons/{yr}?view=proTeamSchedules_wl` → proTeams[].proGamesByScoringPeriod.
- Secret-link gate: `/?key=$APP_SECRET` (in `.env` + Vercel env) sets HttpOnly cookie `fe_key`; all routes incl. /api/espn 401 without it. New device/browser needs the full link once.
- Sleeper full-player dump (~5MB) is cached in localStorage (`sn2`, 24h TTL) as id→[name,age,exp,depthOrder,injuryStatus,team], trimmed to active QB/RB/WR/TE/K/DEF (~3.2k players, 125KB — smaller than the old name-only `sn`). Cache key MUST be bumped whenever that row shape changes, or stale entries deserialize as the wrong type.
- `/api/nfl?feed=injuries|news` (api/nfl.js) proxies ESPN's free public site API — no key, no account. Injuries is ~9MB raw so it's slimmed server-side to ~184KB (name→status/note/date) and memory-cached 1h; on fetch failure it serves stale rather than blanking. News carries ESPN's athlete tags, so headlines map to players.
- ESPN's public news feed is hard-capped at 50 articles (`limit=` is ignored) and the per-team `teams/{id}/news` endpoint returns 200 with zero articles — so news covers ~73 tagged players, about 31 of the draft top 300. draft-research.js logs "News matched N/300" each run; a big drop means the feed changed shape.
- nflverse download URLs use the RELEASE TAG, not the file name: `releases/download/pfr_advstats/advstats_week_rush_2025.csv` (tag `pfr_advstats`), `releases/download/snap_counts/snap_counts_2025.csv`, `releases/download/stats_player/stats_player_week_2025.csv`. Guessing the tag from the filename 404s.
- `advstats_season_rec.csv` covers only 2018–2020 and the weekly `advstats_week_rec_*` has no aDOT or YAC split — so aDOT is computed in draft-research.js as nflverse `receiving_air_yards / targets` (verified: deep WRs ~13, TEs ~5, RBs ~1). snap_counts `offense_pct` is a 0–1 fraction, and rush before/after-contact must be weighted by carries, not averaged across weeks (cross-checks: before+after ≈ yards per carry).
- draft-research.js also pulls nflverse weekly CSVs (target share, air-yards share, WOPR, EPA, CPOE) — free GitHub release files, no key. It tries the current season first and falls back to last season, so the same code works in-season once games are played. Negative air-yards share is real nflverse output (behind-the-LOS targets), not a parse bug.
- `bySeason()` resolves a season **per source**, so usage / snaps / rush-contact can legitimately come from different years once 2026 files start publishing at different times. `usageLine()` tags any bit whose year differs from the line header (`snap share 62% [2025]`) — never remove that or Claude reads stale data as current.
- **Any function reading ESPN `stats[]` MUST filter `seasonId`** — entries from other seasons live in the same array, so omitting it averages two years together. `summarize()` and `ppgOf()` both do; copy the filter into anything new (`--selftest` asserts this).
- Research pool = top 450 **minus K/DST** = 386 players / 21 batches. K/DST were 4 batches of pure waste since `index.html:153` never shows them. The board's own caps must stay ≥ the pool: `index.html:130` fetch limit 450 and `:318` render `slice(0,450)`. The render cap was 300 and silently hid every player past 300 — verify by counting rendered rows in the live app (386), not by reading the config.
- Paid run is resumable: writes `draft-analysis.json` after every batch, and `--resume` skips players already in it (fresh is the default so a re-run never serves stale analysis). A batch that fails twice logs `BATCH FAILED` and is skipped, not fatal; `stop_reason === 'max_tokens'` counts as a failure.
- `--sentiment-list` prints the 27-player shortlist for sentiment queries: ADP ≤150 AND (no 2025 games, or an RB whose team has ≥2 RBs inside ADP 150). Free, local, no network. News/injury flags only reorder — they never qualify anyone. The original rank-gap rule was **removed on Ethan's read of the output**: it surfaced known down years (Jefferson, Lamar) he can already explain, so the crowd added nothing.
- `--sentiment-fetch [--limit N]` (default 3) runs last30days queries per shortlisted player and writes `sentiment.json`, which is then injected into the research prompt like expert-sleepers. **Free**: reddit+youtube keyless, tiktok on the free ScrapeCreators tier — no paid keys. ~60-80s/player (two calls, see below), so it can never run inline over the 386-player pool. Writes after every player; `--refresh` overrides the 5-day TTL. **A source that errors is not silence** — if every source fails the player gets no entry, because storing a failed fetch would invent a fake "nobody is talking about him" signal. Top-3 takes are ranked by likes+comments, which in practice favors YouTube over Reddit.
- **last30days' headless (no `--plan`) query planner silently caps a subquery at 2 sources.** Passing `--search reddit,youtube,tiktok` in one call plans as `sources=[reddit,youtube]` — tiktok is dropped with zero error, zero mention in `source_status`. This reproduces even with an explicit `--plan` JSON supplying 3 sources (the 3rd gets swapped for `grounding`). Verified by comparing planner log lines across `--search reddit,tiktok` (works) vs `--search reddit,youtube,tiktok` (silently 2-sourced). Fix: `sentimentFetch()` in draft-research.js makes **two separate calls** per player — reddit+youtube, then tiktok alone with `--tiktok-creators` — and merges `results`/`source_status`. Never combine tiktok into a 3+-source `--search` list; it will silently vanish.
- `DEBUG_ITEM="player name"` on any draft-research run prints that player's full prompt block — the way to verify a new prompt line actually renders (the dry run only samples the first RB batch).
- `node scripts/draft-research.js --selftest` runs assertions for the mixed-year tag, the `seasonId` filter, and the sentiment selector's entry rule. No network, no cost.
- **Analyst boards live in `draft-guide*.json`** — draft-research.js globs the repo root for that pattern, so adding an analyst is a file drop, not a code edit. Each file carries its own `analyst` name and a `players` map keyed by lowercase ESPN full name. `draft-guide.json` = Joe Holka's top-150 (`overall` + `posRank`, no reasoning). `draft-guide-smyth.json` = Joel Smyth's QB-only video rankings (`posRank` + a real `note`). `draft-guide-smyth-adjusted-ppg.json` = Smyth's "Adjusted Fantasy Points Per Game" study (video, transcribed via `/watch`), covering RB/QB/TE/WR — **note-only, no `posRank`**: it's a stat-splits exercise (strip out injury/backup-QB/committee noise, add playoff-week sample), not a clean 1-N board, so it feeds reasoning into the research prompt but casts zero vote in the board's consensus rank, same shape as the FSC file below. `draft-guide-fsc-archetypes.json` = the FSC RB archetype study (video), **note-only, no `posRank`** — `analystRanks()` skips entries without a parseable posRank, so a note-only guide feeds reasoning into the research prompt and casts **zero** vote in the board's consensus rank. That's the right shape for any source that classifies rather than ranks. `draft-guide-fsc-wr-value.json` = the same FSC/Flock Fantasy channel's 2026 WR value video (point-system scoring by ADP tier + archetype), **note-only, no `posRank`** — he groups WRs into ADP bands and speaks specific scores for only a handful of standouts (Waddle is his single biggest riser, scoring above Lamb/London/A.J. A file with an empty `players` object is skipped entirely. Run logs one `<Analyst> board matched N/M (file)` line per guide. The prompt treats a bare rank as price information only, and a rank WITH reasoning as a named analyst's argument — but never as an override of the usage data. `draft-guide-smyth-rb.json` = Smyth's 2026 RB rankings video (transcribed + frame-read via `/watch` — his on-screen graphic gave exact ranks), **ranked, `posRank` for RB1-36 read straight off the board**; past 36 the video keeps going to a stated "top 50" but the on-screen board wasn't captured for that stretch and he doesn't call out every rank verbally, so only the few explicit numbers he does speak (Croskey-Merritt at 40, Tyrone Tracy at 50, Woody Marks as a bonus 51) got a `posRank` — the rest of that tail (Dobbins, Gainwell, Jordan Mason, Pacheco, Bigsby, Allgeier, Ray Davis) is note-only. - **In-season video takes live in `video-notes.json`, NOT a `draft-guide*.json`.** The draft-guide files are frozen draft-day sources; once games are played a season-long `posRank` is meaningless, so the `fantasy-video-inject` skill now writes week-tagged notes instead. Shape: `notes: { "lowercase espn full name": [{week, analyst, note, source}] }`, `_ttlWeeks: 3`. **Notes are opinion, never value math** — they never touch VBD, tiers, consensus, `_cval`/`_mval`. Three consumers, all TTL-filtered: `waiver-alert.js` (prompt block, explicitly ranked below the usage data), Start/Sit tab, Trades tab (`vnotesOf`/`vnoteLine` in index.html, with a console.assert block). **`week` is required** — a note without it reads as week 0 and expires immediately, which is deliberate: an undated in-season take would read as current forever, same trap as `usageLine()`'s year tag. Served by server.js on a literal path for Vercel tracing.
- `expert-sleepers.json` (repo root) is a hand-curated expert sleeper consensus, gathered by web search — draft-research.js reads it and injects an "expert sleeper call" line per matched player, and the prompt turns that into the `sleeper` badge. Refresh it by asking Claude to redo the search; keys are lowercase ESPN full names. Run logs "Expert sleeper calls matched N/M".
- **Draft sync (bookmarklet)**: `bookmarklet.js` is the readable source; `node scripts/build-bookmarklet.js [localhost]` prints the one-line `javascript:` URL for a Safari bookmark. Clicked inside an ESPN mock draft it scrapes `.completedPick` every 2s and `postMessage`s the FULL pick list to a Fantasy Edge tab it opened with `window.open(url,'fe')`. It opens **zero** network connections, so it can never disconnect Ethan from his draft. Verified in Chrome via Playwright route-interception on the real `https://fantasy.espn.com` origin: picks crossed off, unmatched names surfaced, non-ESPN messages rejected, second click reused the tab.
- Draft-sync listener is `index.html:175`. Its origin check `^https://([a-z0-9-]+\.)?espn\.com$` is **not optional** — without it any page holding a handle to the tab could inject fake picks. It re-renders only when the drafted set or the unmatched list actually changes; rendering on every message would yank the board out from under him every 2 seconds mid-draft.
- Synced picks **disappear** from the board rather than showing struck through, because `hideDrafted` defaults to true — that looked like a failed sync during testing. Turn the "drafted" filter chip off to see them struck through.
- ESPN names that don't match a player in the 400-pool are listed in a red banner above the board (`S.bmUnmatched`), never silently dropped — a missed pick is worse than tapping ✕ by hand. Expect misses on suffixes and D/ST.
- Long-press (500ms) on a draft row toggles a manual `sleeper` mark (localStorage `sl`), merged into the player's badges by `badgesOf()` so the existing badge filter picks it up for free. `tExp` early-returns on `lpFired` so the trailing click doesn't also expand the row.
- **`playoffSeedingRule: TOTAL_POINTS_SCORED` is the TIEBREAKER, not the primary seed order.** The field name reads like a points-only league and it is not. Verified against this league's own 2025 final standings: seed 5 (7-7, 1731.8 PF — the 2nd-highest point total in the league) finished BELOW seed 3 (8-6, 1694.8) and seed 4 (8-6, 1663.6), while points broke the 8-6 tie between 3 and 4. **Record first, points second.** Anything that reasons about seeding (the simulator, any "should I chase points or wins" advice) is wrong in a way that inverts its conclusion if this is read the other way. `scripts/seed-odds.js` pins it in one constant, `SEEDING`, with the counterexample in the comment.
- `scripts/seed-odds.js` = Monte Carlo seed simulator (`--iters N`, `--zero-variance`, `--selftest`, `--out FILE`). Converged: 83.8 / 84.1 / 84.0% top-8 at 5k / 20k / 60k iterations, so 20k is plenty. **The zero-variance control does NOT reproduce projection order** — because seeding is record-first, a deterministic season is decided by the SCHEDULE (who you play each week), not by total points. That is correct behavior, not a bug; the control proves determinism, nothing more. Cosmetic wart: under `--zero-variance` every team's top-8 probability ties at 100/0%, so the summary table's rank column sorts arbitrarily — the authoritative output is the per-seed distribution.
- **nflverse weekly files include postseason rows** (weeks 19-22) — filter on `game_type`/`season_type == REG` or playoff weeks contaminate weekly rates. A player can also have a snap-counts row with no stats row, so an undefined target share there is a real zero, not missing data.
- **Boom rate: a missing player casts no vote.** `boom-rates.json` covers 322/386 of the pool; the 64 misses are overwhelmingly 2026 rookies and players who missed all of 2025 (Brandon Aiyuk and Tank Dell both have genuinely zero 2025 rows — verified in the raw CSV, they are not name mismatches). Absence must never be read as a low boom rate, same rule as an analyst who omits a player. Nicknames are the one real name trap: ESPN's "Hollywood Brown" is nflverse's "Marquise Brown" (16 games that were being silently dropped) — the `NICK` map in `scripts/boom-rates.js` handles it, and a wrong entry there grafts one player's weeks onto another, so confirm both spellings in the raw CSV before adding one.
- **The trade finder needs TWO valuations, not one.** A single shared valuation applied to both sides makes mutual gain nearly impossible by construction — only lineup-slot differences can create joint value, and the tab returned literally zero trades for team 1. Real trades come from *disagreement*: `consensus()` computes `_cval` (his value: ESPN + ADP + every analyst incl. Smyth, then tilted by boom/bust floor) AND `_mval` (their perceived value: ESPN projection rank + market ADP only — what a normal manager sees). `findTrades()` keeps a deal only if it is positive under BOTH, and the UI prints both numbers so he can see why they'd say yes. **Don't "simplify" this back to one valuation.**
- `swap()` in index.html must filter by player **id, not object identity**. `asMarket()` clones players into new objects to re-label their value, so an `includes(p)` identity check silently removed nothing from the counterparty's roster — they "gained" on every trade and the board filled with absurd 1-for-2s in Ethan's favor. Caught only by the `console.assert` IIFE under `findTrades()`; keep that assert.
- **Trades tab has a per-proposal ✕ reject button** (`tradeKey()` + `window.rejectTrade()`, near `findTrades()`). It doesn't trigger new research — `findTrades()` already computes every mutually-good trade each load, rejecting just filters that exact proposal out of the top-25 slice so the next-best one shows. Persisted via `localStorage.tr`; no undo UI yet. The Trades table is the only one on the site with 3 dense columns (Proposal/You/Them), so it's the one place that overflows a phone viewport — it's wrapped in `.tbl-wrap` (`overflow-x:auto`); any new column or button added there needs a phone-viewport check, not just a desktop glance.
- Boom/bust is displayed inline as `💥35% 💀18% [2025]` and expanded to a full line. The `[2025]` tag is load-bearing (same convention as `usageLine()`), and a player absent from `boom-rates.json` renders **nothing** — a 0% boom on a rookie is an actively wrong signal, not a neutral one.
- `draft-guide-smyth-context.json` = the image-only pages of Smyth's PDF (luck metric p18, OL run-block table p14, playcaller table p15, efficiency/gamescript scatters p16-17, 16 player-card previews p21-24), read via `pdftoppm -r 150 -png`. **Note-only**, so Smyth still casts exactly one ranked vote from the PDF board. OL/playcaller/gamescript are team-level and were mapped onto that team's players (team assignments from the keyless Sleeper dump, 184/184). The WR Efficiency scatter's bottom-left cluster (Thomas/Higgins/Harrison/Metcalf/Meyers overlapping) was **dropped, not guessed** — scatter bubble positions are eyeballed and can't be read as numbers.
- **`.nflverse-cache` must never be read for the IN-PROGRESS season.** `weekly()` in boom-rates.js caches the 8MB weekly CSV to disk, but that file is rewritten every week during the season — a cache hit would silently report Week 1 numbers in Week 8 with no error and nothing visible on screen. So the cache is read only when `yr !== SEASON` (a finished season's file never changes). It is still *written* for the current season, and a failed fetch falls back to it with a loud `WARNING` line. Each run logs which path it took (`downloading (in-progress season — cache deliberately bypassed)` vs `cached file`) — verified by watching the cached file's mtime move on a `SEASON=2025` run.
- **Boom/bust needs `MIN_G = 4` games or it abstains.** A rate over 1-3 games is arithmetic, not signal — one good Week 1 renders as a 100% boom rate and looks authoritative. Under 4 games: no chip, the expanded row says "only N games played — too few to rate", and `boomFactor()` returns 1 so the trade finder isn't tilted by noise. The positional bust baseline also excludes thin players — **so any `S.boom` test fixture MUST include `g`**, or every entry drops out of the average, `posBust` goes null, and every factor collapses to 1 (this broke the `risk tilt inverted` assert exactly once). In the 2025 file 106 players are under 4 games; 8 of them are in the 386-player pool, which is why the chip count reads 314, not 322.
- **The stale label is data-driven, never a literal.** `yrTag()` reads `S.boomStale` (set from the file's `stale` flag) — the text originally hardcoded "last season, stale", which would have mislabelled genuinely current 2026 numbers as stale the moment real games existed. An assert covers it.

- **`playerPoolEntry.appliedStatTotal` on a week-scoped `mRoster` call is CUMULATIVE season-to-date, NOT that week's score.** It happens to equal the weekly value in Week 1, so the bug survives exactly the spot-check a reasonable person does — it produced team season totals ~2x too high (3188 vs the real 1657) that still looked plausible in shape. The week's actual score is the `stats[]` entry filtered on `seasonId === SEASON && statSourceId === 0 && scoringPeriodId === wk`; `weekPts()` in `scripts/league-history.js` is the one true reader, **never `appliedStatTotal`**. Same family as the `seasonId` rule above: ESPN packs several aggregations into one field and nothing errors when you take the wrong one. **Sanity-check any team-season total against a known number before trusting it** — this league's 2025 5th seed had 1731.8 PF and the fixed code reproduces 1731.7, which is the cheapest regression test available for this data. Anything outside ~1350–2100 for a 14-week 2025 team is wrong.
- **2025 was NOT a FAAB league — the $1000 FAAB setup is new for 2026.** `mSettings` for 2025 returns `acquisitionType: "WAIVERS_TRADITIONAL"` and `isUsingAcquisitionBudget: false` (the `acquisitionBudget: 100` field is present but dead), so every `bidAmount` in the 2025 data is a genuine `0`. **There is no historical bid data and none can be recovered** — don't go looking. `faabROI()` in league-history.js returns an explicit `faab` flag off `isUsingAcquisitionBudget` so a meaningless `0 pts/$` can never be silently reported as a computed ROI; any future bid analysis must gate on that flag, not on whether bids happen to be zero.
- **`mTransactions2` returns an EMPTY array when called without `scoringPeriodId`** on a completed season — no error, just `transactions: []`, which reads as "this league never made a transaction". Loop the weeks (`{ sp: wk }`) instead. The type enum is `TRADE_ACCEPT`, **not** `TRADE_ACCEPTED` (the latter 400s); full valid set is `DRAFT, TRADE_ACCEPT, WAIVER, TRADE_VETO, FUTURE_ROSTER, ROSTER, RETRO_ROSTER, TRADE_PROPOSAL, TRADE_UPHOLD, FREEAGENT, TRADE_DECLINE, WAIVER_ERROR, TRADE_ERROR`. **When an x-fantasy-filter 400s, read the response's `cause` field — ESPN enumerates the valid enum values for you** rather than guessing. The league communication endpoint (`/communication/?view=kona_league_communication`) is a dead end: 404s "This Communication Group does not exist" for this league with or without a topic filter, four variants tried.
- **`statSplitTypeId` is a FOURTH stat discriminator, alongside `seasonId`/`statSourceId`/`scoringPeriodId`.** A player carries two preseason-projection entries identical on all three of those: `statSplitTypeId: 0` = season TOTAL (Ja'Marr Chase 340.0), `statSplitTypeId: 2` = PER GAME (17.8). Taking the wrong one is a silent ~20x error with nothing on screen. `seasonStat()` in `scripts/league-history.js` pins `0`; a `--selftest` assert covers it. Same family as the `seasonId` rule — ESPN packs several aggregations into one array and never errors.
- **Trade data has three stacked traps.** (1) A `TRADE_ACCEPT` transaction carries an **empty `items` array** — the players swapped live on the `TRADE_PROPOSAL` it points at via `relatedTransactionId` (which stays `status: PENDING` even after acceptance; the ACCEPT is the executed record). (2) **Every executed trade files TWO accepts**, one per participating team, each pointing at a *different* proposal id carrying the *same* players — counting accepts double-counts every trade, so dedup on the sorted player-set signature, not the id. (3) **ESPN returns proposal CONTENTS only to a participant**: with Ethan's cookie, 28 of 28 resolvable proposals involve team 1, and widening the scan to weeks 0–18 resolves zero others. So **league-wide trade net-points is not obtainable and no amount of week-looping fixes it** — `tradeAccuracy()` reports league-wide trade *volume* (accepts ARE returned league-wide; team count = accept count, league total = accepts/2) separately from participant-only net points, with a `scopeNote`. Incidentally this **confirms Ethan is team 1** — previously assumed, now proven by which trades are visible.
- **ESPN preseason projections are systematically inflated — every team finishes under them.** They assume full healthy 17-game seasons, so raw "actual minus projected" ranks injury luck, not draft skill (2025 league average: −616.2 pts, all 12 teams negative). `draftAccuracy()` centers on the league mean (`vsLeagueAvg`) and that centered column is the one to rank on. Never present the raw delta as a skill metric.
- **The consensus draft-board backtest is impossible for 2025 and always will be.** Every `draft-guide*.json` and `analyst-ranks.json` first appears in git in **Aug 2026** — no 2025-era analyst boards exist anywhere in history. Backtesting today's 2026 consensus against 2025 results would be worse than useless. `--draft-accuracy` is the honest substitute: it scores the two inputs that DO have 2025 data (ESPN projection vs the league's own draft order) against actual finish. A real consensus test has to be a *forward* test on 2026.
- **Any "optimal lineup" computation must read the player's own `eligibleSlots`, never infer slots from position** (a benched RB can't fill a WR slot), and must exclude slot ids 20 (BENCH) and 21 (IR) — `lineupSlotCounts` from mSettings includes them with nonzero counts (`20: 7, 21: 1`), so a naive read tries to "start" seven bench players. `bestLineup()` in league-history.js is greedy (most-constrained slot first); a `--selftest` assert covers the eligibility rule. Greedy can only UNDER-state points-left-on-bench, never overstate it — the error direction is known and safe, the magnitude was never measured.
- **A single-study run used to CLOBBER `league-history-<season>.json`** — it wrote `{generated, thatOneStudy}` over a file holding seven others, as valid JSON, with no error and a result that still looks complete. It now **merges** the previous file before writing. Keep the merge when adding a study. Verify by printing the key list, not by eyeballing the file.
- **`scripts/handcuff.js` = RB handcuff hit-rate** (NFL-wide, free, nflverse). 2023–2025: **29 hits / 46 injury windows = 63%**, stable year to year (63.2/64.7/60.0), against 18.8% for speculative RB sleeper picks — **3.4x better**, which is the whole point of the study. Defaults to three seasons (`SEASONS=` env overrides): one season is ~10 windows, too thin to quote. **A bye week is exactly one missed week**, so `MIN_OUT = 2` consecutive absences is load-bearing — a 1-week rule counts every bye in the NFL as an injury (selftest fixture covers it). **63% is the REALIZED handcuff rate** — the back who actually took the carries, not the one drafted as the handcuff in August, which this data cannot recover. Never present it as a guarantee for a specific pick; committees (ARI, NYG 2025) are where it breaks.
- **`boom-rates.js` main() is behind `require.main === module`** so `handcuff.js` can import `weekly()` without kicking off a full boom-rate run. Its rows now also carry `team`/`carries` (unused there). **`draft-research.js` still runs its CLI dispatch at require time and must never be imported** — that's why `csvSplit` is copied rather than shared.
- **`--handcuff-teams` joins those NFL windows onto the league's weekly rosters.** 2025: Ethan owned exactly **one** handcuff (Kimani Vidal) and benched him — 0 pts started, 22.8 on the bench, while Dart that Dihker started the same player five weeks for 56.3. Jalen Kirk owned the most (4) at a 50% start rate. **`startRate` is `null`, not 0, for a team that owned none** — zero would rank "never had the chance" alongside "had it and sat it", same absence-casts-no-vote rule as analyst boards and boom rates. Windows past `matchupPeriodCount` are clipped (no roster to judge), and an unmatched handcuff is reported in `unmatched`, never silently dropped (2025: Kenny Gainwell, genuinely never rostered).
- **`scripts/lineup-alert.js` = the Sunday lineup guardrail** — the in-season fix for the postmortem's headline failure (222.4 bench points, 26% waiver start rate). Reads the lineup ESPN currently has SET, computes the best legal lineup off this week's projections, alerts only when the gap clears `MIN_GAP` (5 pts, env-overridable). Cron `.github/workflows/lineup-alert.yml` runs Sundays 14:00 + 16:30 UTC (10am / 12:30pm ET, pre-kickoff). **A weekly projection is `statSplitTypeId: 1`, NOT 0** — 0 is the season total on the same seasonId/statSourceId/scoringPeriodId, so grabbing it is a ~20x silent error (same family as the season-total trap). **LOCKED = the player already has a week-N actual entry (`statSourceId: 0`)**; locked starters keep their slot and their slot comes off the board, locked bench players are never recommended. It cannot tell "game not started" from "game started, zero points yet" — safe only because it runs before the 1pm window. State (`lineup-state.json`, gitignored, actions/cache) holds one advice signature per week so identical advice never re-fires.
- **`league-history.js` and `boom-rates.js` are now importable; `draft-research.js` still is not.** Both are behind `require.main === module` and export their reusable pieces (`bestLineup`/`SLOT`/`STARTABLE`, and `weekly`/`csvSplit`). Keep the guard when editing either — lineup-alert.js imports `bestLineup` and would otherwise kick off a full 8-study run on require.
- **Start/Sit is a win-probability tab, not a projection list.** Because the league seeds record-first, the decision is "does this raise my chance of winning THIS matchup", which disagrees with projected points exactly when the matchup is lopsided. Each side is modelled `Normal(Σ weekly projections, Σ variance)`; win% is a normal CDF on the difference. **Volatility is a coefficient of variation (`sd/mean`), never raw sd** — the ratio transfers from last season to this week's projection, the absolute number doesn't. `boom-rates.js` now writes a per-player `sd` (sample, n−1; **`null` for a 1-game player** — one game has no measurable spread). An unrated player gets his position's median cv, never zero variance, same absence-casts-no-vote rule as everywhere else. **From a points-optimal lineup every legal swap costs projected points**, so the only calls shown are "costs points, buys win probability" — that is the intended shape, not a bug. Players are assumed independent (a QB+WR stack is really correlated); K/DST are excluded from both sides symmetrically. Needs the `mMatchup` view in `load()` for the opponent, and `oppOf()` keys on **`matchupPeriodId`**, not scoringPeriodId.
